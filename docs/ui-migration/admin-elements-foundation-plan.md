## Import boundaries and capability gaps

1. **Menu data is not presentation-independent yet.** `Components/AppMenu/useMenuData.jsx` imports feature state modules to read their names. Separate stable route identifiers/metadata from feature components before sharing this model. Do not import the whole legacy registry into the Elements entry.
2. **Navigation services bind to the existing router singleton.** [Services/Navigate](/Users/liamyoung/Repos/Gecko-Admin-Web-App/App/src/Services/Navigate/index.jsx:1) imports `Router`; [RouterWrapper](/Users/liamyoung/Repos/Gecko-Admin-Web-App/App/src/Router/RouterWrapper/index.jsx:1) imports the configured router. Make router construction/registration entry-specific while preserving the existing navigation interface. Trace consumers to avoid two routers or accidental legacy registration.
3. **Presence action logic imports styles by association.** `prepareHandleAvailabilityChange` is exported from the styled legacy banner module. Extract that function and its necessary state effects before reuse.
4. **Sidebar unread indicator has no documented slot.** Admin supplies an unread `indicator` class in its menu model. Elements AppSidebarNav types expose id/label/icon/href or children, without an unread prop. Request an owning-library capability; do not silently omit it or inject styling through labels. [Implementation](../../packages/ui/src/components/app-sidebar.tsx).
5. **Active state is route-based in Admin and path-based in Elements.** Elements matches exact href or a descendant path; Admin groups several differently named record/list states. Prove a canonical active-path adapter for every migrated family. If it cannot express the existing state relationship, request a library API extension rather than change destinations to force highlighting.
6. **Account header colour conflicts with the library contract.** Admin applies `account.color`; Elements owns the header chrome token and forbids consumer restyling. The account logo is supported. Preserve the colour requirement as an explicit unresolved parity item: agree a library-supported branding policy before calling the shell complete.
7. **The local Admin development guide prescribes legacy FormView/PageLayout.** For this migration, the user's explicit Elements-only presentation requirement takes precedence. Preserve the guide's Commands, translations, data ownership and routing conventions; do not import Bootstrap-backed page components simply to satisfy a legacy composition example.

A full transitive production bundle audit remains an implementation gate. This source audit identifies concrete import hazards; it does not certify a clean dependency graph.

## Persistence contract to implement

| State                                                         | Owner / lifetime                                                  | Reset or restoration rule                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Session, account, permissions, sockets                        | Application providers above route outlet                          | Intentional account/logout boundary; do not recreate per route. Preserve existing cross-tab identity resets.                                                                                                                                                                   |
| Sidebar preference                                            | Existing persistent preference adapter                            | Restore synchronously on shell mount; persist user changes.                                                                                                                                                                                                                    |
| Record identity, page header, shared actions and shared draft | Persistent parent record route keyed by account + record identity | Retain identity/layout across sibling tabs. Retain drafts where the workflow promises sharing; preserve existing dirty-leave decisions for independent editors. Guard disposal on leaving or changing identity. Do not persist sensitive drafts to browser storage by default. |
| List query, sort, filter, pagination                          | URL with one coherent history update                              | Cold URLs and Back/Forward must restore the same effective query. Selection and scroll require workflow-specific rules, not automatic indefinite persistence.                                                                                                                  |
| Reference data                                                | Existing query client and shared hooks                            | Retain during route navigation; invalidate on relevant mutations and identity changes.                                                                                                                                                                                         |
| Static titles and breadcrumbs                                 | Route metadata                                                    | Available without DOM scraping or a delayed timer.                                                                                                                                                                                                                             |
| Dynamic title and action eligibility                          | Parent resolves / scoped metadata                                 | Publish only the correct record/editor/action structure. Unknown identity gets a reserved region; permissions remain authoritative.                                                                                                                                            |
| Refresh errors                                                | Affected content region                                           | Preserve useful data and shape; errors cannot become empty success.                                                                                                                                                                                                            |

The current route-resolve convention is useful: resolve the destination before committing it, keep the current page visible during the transition, and reserve initial content on a cold load. Do not mount the destination with guessed metadata. Stable parent identity and one scroll owner follow [Elements application patterns](../../packages/ui/docs/application-patterns.md).

These are intended acceptance rules, not a claim that the current app already provides every form of persistence. The companion audit identifies the current differences.

## Foundation implementation boundaries

### Isolated entry

Proposed new files follow Admin folder conventions: `App/elements/index.html`, `App/src/Elements/main.tsx`, `App/src/Elements/App/index.tsx`, `App/src/Elements/Styles/index.css`, `App/src/Elements/Router/index.tsx`, and `App/src/Elements/Shell/index.tsx`. Exact build entry naming should follow the Vite proof, not become a business-code dependency.

- Change `App/vite.config.js` to build both entries and implement/test the local deep-link fallback. Inspect the associated hosting function before adding the deployed Elements path rule.
- Pin a verified Elements package and supported peers; Admin already declares React/React DOM 18.3.1. Add matching `react-is` if still absent. Use public package exports, not source aliases.
- Choose only Elements Tailwind integration for the new entry, with explicit consumer source registration. Read the dependency policy before dependency changes. Do not add Tailwind or Elements globals to legacy `main.jsx`.
- Separate asset base, router base, canonical legacy destination and API base configuration. A single string replacement across URLs is not sufficient.
- Keep the legacy build operational; verify both compiled documents and their reachable CSS assets.

### Elements-local adapters and unchanged shared services

- Adapt `App.jsx` boot/context sequencing for a persistent Elements root with explicit startup failure/retry.
- Adapt account switching, presence handling and user-menu actions inside `src/Elements`; reuse unchanged Commands and services. Keep the existing presentation components/hooks and legacy entry untouched for this experiment.
- Separate menu definitions and route identifiers from component imports.
- Make router setup accept entry-specific states/base without duplicating business guards. Keep Angular redirect behaviour for applicable destinations and explicit full-document fallbacks for unmigrated React states.
- Reuse Commands, API requests, authentication and shared query hooks after tracing their imports. Extract only dependencies demonstrated to contaminate the new presentation graph.
- Keep telemetry, translations and socket ownership once per document; review cleanup on identity change/unmount.

### Persistent shell

Implement the shell parity matrix above using approved Elements components. Keep App Header and App Sidebar above the route outlet; keep record headers above child outlets. Replace global Bootstrap surfaces with Elements adapters. Resolve listed library gaps explicitly rather than marking an incomplete shell as done.

Do not migrate multiple product pages until this foundation passes the acceptance scenarios below.

After the foundation gate passes, follow the pilot and rollout sequence in the [migration plan](README.md) and record coverage in the [workflow ledger](workflows.md).
