## Scope and inventory

Parent route /settings/contact_fields redirects to contact_fields.list (/list); sibling contact_fields.groups is /groups. Header and Settings breadcrumb say Contact fields and groups. Keep a persistent parent header, tabs and shell through tab changes. Field groups tab requires CONTACT_FIELD_GROUPS_VIEW. Creation buttons are tab-specific: Create new contact field; Create new field group requires CONTACT_FIELD_GROUPS_CREATE. Preserve existing React contact_field and contact_field_group editor destinations, including id=new. Do not migrate those editors in this parent-list slice. Existing settings access requires FIELDS_VIEW; retain all endpoint permission enforcement.

Contact fields: columns Label, Group, Type, Template tag, Matchable and system lock. Group resolves against complete group reference collection, with '-' fallback. Type formatting replaces underscores and capitalises matching source. Matchable is Yes only for numeric 1; system lock appears only for numeric 1. Rows navigate to contact_field. Conditional View option list action only when option_id exists; destination /#/settings/options/{option_id}. Free-text server search, multi-select Group filter, pagination/page size and Change field order menu. No current sorting controls (columnKeys empty), selection/bulk actions or field deletion on this list. Filter serialisation: one group id, or @id|id for multiple. Group query source must be complete rather than current table page.

GET /fields retains field_type=contact, include=option, option_rfield=name, editable=true, keyword, page/per_page and group filter. Default order is order|ASC. API valid_orders are label, created_at, order; do not infer sorting for Type/Group/Tag/Matchable. User has not requested new API capabilities for this slice.

Field groups: columns Name, Number of fields (fieldCount), and Created at with Created by on a second line (createdAt/createdBy API properties). Sortable Name and Date created; default created_at DESC must show its arrow. Pagination/page size. No current search or filters; Command does not accept them. Row navigation and Configure require VIEW; Delete requires DELETE, opens confirmation, deletes and refreshes. Destructive menu item must be last with divider. Retain failure feedback and page clamping after deleting the final row. Endpoint GET /contact-field-groups uses page/perPage/orderBy/sort (distinct from /fields parameter names), DELETE /contact-field-groups/{id}. Existing successful delete feedback is Field group removed; any wording change must be identified as a requested convention change, not an assumed API behaviour. No bulk deletion.

Reorder dialog: fetch complete contact fields and field groups. Profile contains non-system fields without a known group; group sections appear alphabetically; System contains fields where both system and is_calculated are truthy. Empty sections excluded. Each section starts expanded, may be collapsed, and has an independent sortable list. Reordering is within a section only: do not add cross-section reassignment or draggable sections. Preserve buildReorderSections/buildUniqueFieldOrderMap logic and globally contiguous unique id/order payload. Save with no changes closes without POST. Changed save POST /fields with {fields:[{id,order}]} then invalidates contact-field cache and refreshes parent list; failure reports toast and retains dialog. Cancel discards local reorder. Dialog payload survives exit; explicit open state separate from data.

Initial loading: known header/tabs/table stay mounted with table skeletons. Background requests retain rows with updating overlay. Empty collection, zero query matches and failed request are distinct states. Immediate query convention replaces submit-button search/filter; no debounce. Store preferences only in Elements namespace; verify refresh, Back/Forward, tab state and page-size persistence. No parent form/dirty-leave guard; child editor guards remain original. Reorder local cancellation is its own workflow.
